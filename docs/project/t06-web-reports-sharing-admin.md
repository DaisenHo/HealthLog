# T06：Web 报告、分享、管理与剩余中文文案

对应 [Web #6](https://github.com/DaisenHo/HealthLog/issues/6)，基于 T05 提交 `16458d019dcc8881faee887bf6e0945c715880cb`。本任务完成 Web 剩余中文范围，不代表 iOS、设备同步或 M1 正式部署验收完成。

## 范围与语言归属

补齐报告与分享视图、导出/导入说明、管理员设置、其他设置、Coach/Insights 外围文字、通知/Telegram 帮助、成就、密码强度、版本、搜索与快捷键。沿用前序任务的译文，全部 10,910 个可翻译键均有归属；181 项品牌、药名示例、单位、编码或纯格式模板保留原值，逐项见 [覆盖清单](t06-localization-coverage.json)。没有整段英文占位例外。

79 个受限问卷题目/选项继续不进入中文 catalog，由现有 `instrumentText` 读取原版英文；不增加受验证语言白名单或改动评分、回顾期与许可。用户输入、药品名称、数值、来源、单位、账户时区与日期格式保持原值。

本人导出优先使用显式导出语言，其次为当前操作者的账户语言；无有效账户语言的旧客户端继续使用 cookie/浏览器提示。查看受委托记录时，报告语言属于操作者，数据与单位/时区仍属于记录本人。公开分享 HTML/PDF/FHIR 保留访问者语言语义，FHIR REST 文档使用记录本人账户语言及已保存范围。既有近期身份确认、角色权限、模块开关、限流、冻结范围和保险信息限制保持不变。

## 报告与模型输出

PDF 在服务端按需读取本地 Noto Sans SC 常规/粗体静态字体，覆盖中文界面以及英文报告里的汉字用户原文。字体来自 Google Fonts，保留 SIL OFL 许可、源文件摘要及生成方式；不将健康内容发送至字体服务。沿用 Helvetica family 的文档实例别名，现有分节和表格不必维护另一套渲染器。中文请求缺少字库时明确失败，不返回乱码报告。部署追踪包含字体，Docker 与 standalone 仍使用原有 public 资源复制方式。

FHIR 仅中文分支翻译应用自有标题、叙述、病史、生活情况和非诊断说明；官方 LOINC/SNOMED/HL7 `coding.display`、编码、引用、日期、数值、单位及用户原文保持原样。未指定语言及其他既有语言继续使用原有英文 FHIR 文本，未扩大数据收集或选择范围。

模型路径沿用已经审阅的英文机器策略，附加简体中文输出要求；协议字段、枚举、药名与单位保留。补齐中文剂量/风险/因果合同匹配、按原用药计划判断的延续服药豁免、中文句界、引用覆盖和数值单位校验，并提供中文拒绝说明。英文联合匹配仍保留。没有改动 AI 开关、提供商、同意流程、调用触发条件、后台调度或付费调用范围；实际生成质量仍取决于已配置模型。

## 验证方式

沿用公开 PDF/FHIR 构建函数、现有渲染器和真实 HTTP/UI 边界。虚构账户在英文桌面与中文窄屏依次操作；真实下载 PDF/FHIR/ZIP，读取 PDF 文本、检查 ZIP 内报告与 bundle、核对 CSV 表头与原始枚举，验证口令前拒绝/解锁后读取、访问者切换语言和普通账户管理权限拒绝。管理员通知测试的成功/未配置渠道/失败提示，以及提醒检查的星期、时间窗说明和汇总采用中文；发送逻辑、收件人自己的通知语言及状态码不变。管理员页面按原角色门禁读取，语言切换前后核对 AI 开关、账户单位和时区。

针对性测试覆盖中文无空格文本、药名邻接、错误剂量延续、临床风险拦截、允许的事实/转诊说明、中文日期/小数/千分位、时长与血糖单位隔离、单句人群参考豁免，以及 FHIR XHTML 单次转义、编码与数值不变。所有新增词条通过完整 catalog 和精确例外清单约束。
