# T04：Web 用药、目标范围与提醒中文闭环

对应 [Web #4](https://github.com/DaisenHo/HealthLog/issues/4)，基于 T03 提交 `b20dc60908103832e295c962e288ad742abbb611`。此任务不代表 M1 全部完成或正式发布。

## 范围

沿用现有国际化机制，覆盖用药列表、创建/编辑向导、服药与跳过、历史、计划与疗程、库存、注射部位、副作用、效果分析及导入/导出文案；覆盖服药、检查、心情、库存不足与 Coach 提醒，通知矩阵及现有发送渠道设置。药物成分编辑器使用的营养素名称、相关 API 错误提示，以及发送渠道共用的连接测试状态/错误一并覆盖。

精确范围见 [词条覆盖清单](t04-localization-coverage.json)：1,388 个键，1,366 个有中文文案，22 个保留药物通用名、品牌/协议、临床编码、单位或纯格式模板。既有 `targets.*` 的 93 个指标范围词条沿用 T03；通用每日/每周/每月目标引擎仍属于后续 M4。

仅扩展中文 catalog，并修正用药向导、导入/导出、阶段配置、副作用、令牌及目标范围操作失败时直接显示服务端英文的路径。优先采用已有机器错误码翻译，无对应翻译时使用现有本地化兜底。其他语言、药名、用户输入、剂量、计量单位、临床编码、计划、计算及同步/调度规则保持原有语义。

## 提醒来源与权限

保留现有 HealthLog 用药与提醒功能，不在本任务决定 Apple 健康替代方式。已选择由 iPhone 管理提醒时，详情继续显示只读说明，并隐藏 HealthLog 提醒开关。记录来源、权限和只读限制保持不变。

通知正文沿用服务端账户语言和现有模板插值。未开启新渠道、配置真实凭据或改变推送任务，不把模板验证写作真实设备推送验收。

## 验证方式

- 公开渲染测试检查中文依从率标签和既有数值；以中英两种语言检查 iPhone 管理分支隐藏开关。
- 服务端翻译测试检查中文提醒正文保留虚构药名、剂量、时间和剩余分钟。
- 扩展既有独立用药账户浏览器旅程，通过账户设置选择中英文，正常调用真实 API 创建虚构药物、服用、跳过、查看历史及保存提醒设置。用一次被服务端拒绝的无效传输请求检查本地化错误，再重试原表单。
- 在桌面和窄屏检查历史及提醒设置，刷新核对持久化；额外通过现有目标范围编辑器验证中英文校验、保存和数值回读。
- 使用独立 PostgreSQL 测试容器，夹具仅清理专属虚构账户；范围编辑测试恢复原来的覆盖值和账户语言，不连接真实健康库。

## 验收结果

- `pnpm typecheck`、`pnpm format:check` 和生产构建通过；`pnpm lint` 无错误，保留基线中的 3 条警告。
- `pnpm test --maxWorkers=2`：2,843 个文件通过，35,094 项通过、16 项既有跳过，无失败。源代码长度守卫通过；未修改守卫、基线、超时或重试次数。
- standalone 生产构建上的全部 5 条相关浏览器旅程通过（21.1 秒），包括中英、桌面/390 像素窄屏、失败后重试、服药/跳过/历史、提醒保存、权限拒绝、每周计划及目标范围。
- 已查看中文窄屏和目标范围截图，并归档 10 张中英截图；生产服务端 catalog 和首屏资源均包含最新中文文案。
- 双轴评审最终无未解决问题。连接测试文案、状态误译、导入引用和目标范围标题遗漏已修复。向导复用现有 API 包装器并显式保留原来的无超时保存行为。

正式部署、设备推送、HealthKit 与真机验证不属于本次结论。
